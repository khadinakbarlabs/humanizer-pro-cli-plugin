# Humanizer PRO 0.3.0

A writing session now starts with a useful next step: plan, review, revise, or keep a strong original. Approved global/project preferences carry context between sessions; current instructions win and the editing brief exposes their sources. Only existing mode/style options reach the rewriting service, so this release does not claim a custom voice model.

Local comparison flags changed numbers, ISO/English dates, links, quotations, negation and protected terms. These checks are partial; the exact service result remains separate from assistant suggestions. Optional structured preferences and text-free session receipts use a separate private plaintext store. Accepted/edited/rejected feedback never silently changes preferences. Users can show, export and reset local data.

Private HTML reports show saved activity, reported word usage, feedback coverage and unknown outcomes. Reports and comparisons are self-contained and work at narrow widths. Comparison files contain their supplied passages; report files contain metadata only. Included visual examples are clearly labeled synthetic test data.

Validated weekly-report, review-reminder and deadline specifications can be handed to an available documented local host scheduler with user approval and actual task-ID verification. The package installs no scheduler or daemon and does not perform background rewrites. A plan alone is not scheduled.

Account endpoints, OAuth permissions, service processors, billing and purchase restrictions are unchanged. No dependencies, installation hooks, telemetry or feedback upload were added. Local operations never open the OAuth store or contact the service.

Validation: 38 focused tests; 20 isolated command-workflow checks; current Claude Code 2.1.289 strict plugin and marketplace validation; actual generated report and comparison checked at 390px and desktop widths. A Claude conversational smoke test encountered a host 429 session limit before the skill executed. Actual host timer execution remains unverified. These are release checks, not directory approval.
